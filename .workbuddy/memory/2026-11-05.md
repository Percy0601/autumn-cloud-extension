## 待修问题（按优先级）
1. 配置中心链路是半成品：只有 ConfigCenterClient + 孤儿 ConfigRefreshListener Bean，没有任何 PropertySource/Environment 注入，也没有任何 addListener 调用；@RefreshScope + @Value 示例实际读本地值，改远程配置不会刷新。ConfigListener(Consumer<ConfigChangeEvent>) 与 addListener(Consumer<String>) 类型不兼容。
2. 泳道标签语义不一致：代码主干是 `main`（Traffic.DEFAULT），示例 provider 配 `autumn.discovery.traffic=default`，导致无 header / 未知标签请求匹配不到 main → 回落"放行全部"，会随机打到 gray 实例；单测用 main 标签所以全绿，未覆盖示例配置。
3. 静默失效的配置键：`autumn.config.enabled`（无 @ConditionalOnProperty 实现）、`autumn.config.default-group` / `default-namespace`（实际前缀是 autumn.config.nacos/consul）。
4. 拆分后仍需显式写 `autumn.discovery.backend=xxx` / `autumn.config.backend=xxx` 才激活 starter，漏写静默不生效（无 matchIfMissing）。
5. 文档过期：docs/usage.md 整体是拆分前版本（单 starter artifactId、apache-httpclient5、trafficlabel、X-Autumn-Traffic-Label、header-name）；application.properties 注释同样过期；README 纯 Java API 示例类名 `ConsulServiceDiscoveryClient` 不存在、addListener 的 lambda 参数类型写错；README 配置项表与代码有出入。
6. 实现质量：Nacos 配置长轮询用 String.hashCode 冒充 MD5、getConfig 手写字符串截取解析 JSON；Consul blocking query 用 response.hashCode 当 index 且不读 X-Consul-Index 响应头。
7. 测试偏薄：无 ApplicationContextRunner / Spring 上下文集成测试，自动装配与配置绑定问题测不出来；拆分后未重跑组播端到端冒烟。
